1. Purpose

Claude's own judgment is not a security boundary. A system prompt that says "never refund more than $500" or "never run rm -rf" has a non-zero failure rate. The examples in this directory move those rules out of the prompt and into the harness, where code enforces them deterministically before and after every tool call.

MechanismWhat it gives youShown in
Hooks
PreToolUse / PostToolUse		 Block, rewrite, or annotate a tool call with a script that Claude cannot bypass. hooks-example/
security-skill/
Permissions
allow / deny lists		 Auto-approve safe commands, hard-block dangerous ones, prompt for everything else. security-skill/
Skills and commands Package a repeatable security review or workflow as a /slash-command. security-skill/
command-example/

2. Scope

In scopeOut of scope
  • Claude Code CLI projects, interactive and -p non-interactive
  • MCP tools you write yourself and want to guard with business rules
  • Prompt-injection defence for file reads, shell output, and web results
  • Destructive-command blocking: rm -rf, curl | bash, force push, raw disk writes
  • Credential-path protection: ~/.ssh, ~/.aws, ~/.gnupg, /etc/shadow
  • Structured tool errors that prevent retry loops on fraud or compliance blocks
  • Securing the Claude API itself or the Anthropic platform
  • Network or OS sandboxing beyond what Claude Code provides
  • Authentication and secrets management for your own services. The examples read API keys from environment variables and stop there.

3. Installation

Each example is self-contained inside its own directory and only writes inside that directory. Nothing is installed system-wide unless you follow one of the optional "make it global" steps, and each of those has a matching row in the Uninstall table.

Get the code

git clone https://github.com/ruchirtewari/agent_security.git
cd agent_security

security-skill
hardening hooks		 Per project of your own. Opt-in; not wired by default. Copy the scripts and back up the existing settings so uninstall is a one-line restore: 
cd /path/to/your-project
mkdir -p .claude/hooks
cp /path/to/agent_security/security-skill/.claude/hooks/{restrict-bash,sanitize-read,validate-output}.py .claude/hooks/
cp .claude/settings.json .claude/settings.json.bak 2>/dev/null || true
Merge this into .claude/settings.json, keeping any keys already there: 
{
  "hooks": {
    "PreToolUse": [
      { "matcher": "Bash", "hooks": [{ "type": "command", "command": "python3 .claude/hooks/restrict-bash.py" }] },
      { "matcher": "Read", "hooks": [{ "type": "command", "command": "python3 .claude/hooks/sanitize-read.py" }] }
    ],
    "PostToolUse": [
      { "matcher": "Bash|WebSearch|WebFetch", "hooks": [{ "type": "command", "command": "python3 .claude/hooks/validate-output.py" }] }
    ]
  },
  "permissions": {
    "deny": [
      "Bash(rm *)", "Bash(sudo *)", "Bash(curl * | *)", "Bash(wget * | *)",
      "Bash(chmod 777 *)", "Bash(dd *)", "Bash(mkfs*)", "Bash(git push --force *)"
    ]
  }
}
Verify a hook outside Claude Code before relying on it: 
CLAUDE_TOOL_INPUT='{"command":"rm -rf /"}' python3 .claude/hooks/restrict-bash.py; echo "exit=$?"
# [security hook] BLOCKED: destructive rm -rf on root/home/glob
# exit=1
security-skill
nightly advisor		 User crontab. Optional. Edit the REPO path at the top of nightly-suggestions.sh, then: 
crontab -e
# 0 8 * * * /absolute/path/to/.claude/hooks/nightly-suggestions.sh
command-example Project-local by default. Optional global copy. No install step for use inside command-example/. To make a command global: 
mkdir -p ~/.claude/commands
cp command-example/.claude/commands/status.md ~/.claude/commands/
Roll out hooks gradually. Start with the deny list and restrict-bash.py only, then add sanitize-read.py once you have confirmed it does not block files you need. A hook that blocks Read on a false positive can stall a session.

4.1 hooks-example/ — MCP tool with Pre/PostToolUse hooks

FileStageRole
mcp_tools/refund_server.pyMCP FastMCP server exposing process_refund(customer_id, order_id, amount, reason). Returns structured errors with errorCategory and isRetryable.
.mcp.jsonconfig Registers the server with Claude Code under the name refund-tools. Injects REFUND_API_KEY from the environment.
.claude/settings.jsonconfig Wires both hooks to the matcher mcp__refund-tools__process_refund.
.claude/hooks/pre_process_refund.pyPreToolUse Blocks refunds over $500 with exit 2 so Claude sees a clear error and does not retry. Normalises IDs on the way through.
.claude/hooks/post_process_refund.pyPostToolUse Appends to audit.log and enriches the result with isRetryable, errorCategory, agentHint.
run-refunds.shtests End-to-end batch test. Generates 8 cases, runs each through claude -p, scores the audit log and traces.
test-refunds.json, traces/TC-*.jsonltests Generated test data and per-case stream-json traces.

Test cases exercised by run-refunds.sh

IDAmountExpectedWhat it proves
TC-01$150.00successStandard refund below threshold passes both hooks
TC-02$499.99successBoundary one cent under the limit is allowed
TC-03$500.01pre_hook_blockedBoundary one cent over the limit is blocked
TC-04$1200.00pre_hook_blockedLarge amount is blocked with a manager-approval message
TC-05-$50.00validation_errorNegative amount returns a structured, non-retryable error
TC-06$0.00validation_errorZero amount returns a structured, non-retryable error
TC-07$75.00transient_errorOrder ID ending in FAIL simulates an outage and is marked retryable
TC-08$200.00permission_errorUnset REFUND_API_KEY surfaces as a permission error, not a silent success

See hooks-example/README.md for the full flow diagram, exit-code table, and the anti-patterns the design avoids.

4.2 security-skill/ — Security assessment skill plus hardening hooks

FileStageRole
.claude/skills/security/SKILL.mdskill The /security skill. Asks 12 questions across three domains, scores gaps, then offers to implement fixes.
.claude/hooks/restrict-bash.pyPreToolUse
on Bash		 Regex denylist: rm -rf /, sudo rm, curl|sh, fork bombs, dd to raw disks, mkfs, force push to main, credential paths. Exit 1 blocks.
.claude/hooks/sanitize-read.pyPreToolUse
on Read		 Scans the target file for injection phrases such as "ignore previous instructions" or <system> and blocks the read.
.claude/hooks/validate-output.pyPostToolUse
on Bash, WebSearch, WebFetch		 Cannot block a result, so it prepends an explicit "treat as UNTRUSTED" warning when injection patterns appear. Two-tier matching limits false positives.
.claude/hooks/nightly-suggestions.shcron Feeds recent git log, status, hooks, and skills to claude -p and writes a prioritised next-steps report.
Security.mddocs Architecture overview of the control stack, permissions config, remaining gaps, and how to extend each layer.
security-skill.mddocs Copy of SKILL.md kept at the top level for reading outside Claude Code.

Assessment domains covered by /security

DomainQuestions askedFixes offered
A. Agentic orchestration Minimum footprint, output validation, injection defence, action gates for irreversible operations. Code patterns: sanitiser, schema check, destructive-action gate.
B. Tool and MCP design Path privilege, input parameterisation, error strategy, single responsibility. Code patterns: path-traversal guard, parameterised SQL and subprocess, exception vs. structured error split.
C. Claude Code config PreToolUse hooks, allow and deny lists, CI -p mode, CLAUDE.md security section. Writes hooks and permission lists into .claude/settings.json, appends a security section to CLAUDE.md.
Not wired by default. The three hook scripts in security-skill/.claude/hooks/ are not referenced by any settings.json in that directory. They do nothing until you add the hook configuration shown in Install and use.

6. Extending

GoalWhere to change
Block a new dangerous command Append a (regex, reason) tuple to DENYLIST in restrict-bash.py.
Catch a new injection phrase Add the regex to INJECTION_PATTERNS in both sanitize-read.py and validate-output.py.
Guard a new MCP tool Follow the six-step recipe under "Adapting to a new tool" in hooks-example/README.md. The matcher format is mcp__<server>__<tool>.
Auto-approve a safe command Append "Bash(your-command *)" to permissions.allow in .claude/settings.json.
Reduce permission prompts Run /fewer-permission-prompts to generate an allowlist from your transcripts. Hooks and deny lists keep enforcing even under --dangerously-skip-permissions.
